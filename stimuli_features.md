# Computational Stimulus Features

For stimulus descriptions (images, audio, movies, metadata), see
[Stimuli](stimuli.md).

Stimuli are scored by a family of extractors — **viz2psy** (visual),
**aud2psy** (audio), **word2psy** (text) — consumed through **psytwill**.
Outputs follow a shared column and sidecar convention so features from
different extractors can be joined on a common stimulus identifier.

> **Two layouts coexist right now.** A migration to the current
> `derivatives/stimuli_features/` layout is **in progress**. The older
> per-set files under `stimuli/` are still on disk, still valid for what
> they contain, and have **not** yet been re-extracted into the new layout.
> The two use different column conventions — check which one you are
> reading. Details in [Layouts](#layouts) below.

---

## Stimulus registry (canonical IDs)

`stimuli/stimulus_registry/` holds the dataset-owned `stimulus_id` tables —
one TSV per set. Consumers validate against these and never invent IDs.

| Table | `stimulus_id` form | Rows |
|---|---|---|
| `shared1000.tsv` | image filename stem (`shared0001_nsd02951`) | 1000 |
| `twp1000.tsv` | the word itself; voice is a reserved column | 1000 |
| `movies.tsv` | kebab-case title, leading article dropped (`adventure-time`) | 60 |

Generated by `mmmdata/scripts/build_stimulus_registry.py` (`--check` compares,
`--validate-events` asserts every events-file reference resolves). The
registry's own `README.md` documents the events→ID join rules and known gaps.

## Layouts

### Current — `derivatives/stimuli_features/`

The Contract B layout. Every CSV carries `stimulus_id` as its first column,
fixed-width feature indices (`clip_000` … `clip_511`), and a `.meta.json`
sidecar recording `schema_version`, `extractor`, `extractor_version`, and the
model **checkpoint** used.

```
derivatives/stimuli_features/
├── shared1000/
│   ├── clip.csv + clip.meta.json                 # CLIP image embeddings
│   ├── caption.csv + caption.meta.json           # BLIP captions
│   ├── caption_clip_text_{words,chunks}.csv      # CLIP text arm over captions
│   ├── caption_ebind_text_{words,chunks}.csv     # EBind text arm over captions
│   └── ebind.csv + ebind.meta.json               # EBind shared-space embedding
├── twp1000/
│   ├── clip_text_{words,chunks}.csv
│   └── ebind_text_{words,chunks}.csv
├── movies/                                       # one directory per movie (60)
│   └── <movie-stimulus-id>/
│       ├── clip.csv, caption.csv, ebind.csv
│       ├── caption_{clip,ebind}_text_{words,chunks}.csv
│       └── ebind_audio_frames.csv                # EBind audio arm
├── psytwill/                                     # psytwill-assembled feature tables
│   ├── shared1000_ebind_features.parquet
│   └── movies_ebind_features.parquet
└── figures/stimulus_space/                       # joint-space diagnostic figures
```

Time-varying features (movies) are on a **0.5 s grid**.

**Coverage note:** the sets above currently carry the CLIP / BLIP-caption /
EBind families. The remaining viz2psy models (see table below) have **not**
been re-extracted into this layout yet — for those, use the legacy files.

The word set (`twp1000`) has a **text arm only**. An EBind audio arm was
evaluated on the spoken words and carried no lexical signal, so it is not
published for that set.

### Legacy — `stimuli/<set>/viz2psy_scores.csv`

The original all-models extraction (viz2psy 0.5.0, February 2026). Indexed by
`filename` rather than `stimulus_id`, with human-readable feature column names
(`memorability`, `Adoration`, `Aesthetic Appreciation`, …) predating the
fixed-width convention. No `schema_version` in the sidecar.

```
stimuli/
├── shared1000/viz2psy_scores.csv          # 1000 rows × ~2900 cols
└── movies/viz2psy_scores/
    ├── viz2psy_cue_scores.csv             # cue-image features (60 rows)
    └── <Movie_Name>_scores.csv            # per-movie frame-level features
```

These files are the only source for the 11-model feature set until the
extraction campaign finishes. Join them to the registry on the image filename
stem.

## viz2psy models

The 11 visual models in the all-models extraction:

| Model | Output | What it measures |
|-------|--------|------------------|
| `resmem` | 1 score | Image memorability (0–1) |
| `emonet` | 20 scores | Emotion category probabilities |
| `clip` | 512 dims | Vision-language embeddings (CLIP ViT-B/32) |
| `caption` | 1 string | Natural language caption (BLIP) |
| `dinov2` | 768 dims | Self-supervised visual features (DINOv2 ViT-B/14) |
| `gist` | 512 dims | Spatial envelope descriptor (Gabor filters) |
| `places` | 467 scores | Scene categories (365) + SUN attributes (102) |
| `llstat` | 17 scores | Low-level stats (luminance, contrast, color, edges, frequency) |
| `saliency` | 576 dims | Fixation density prediction (24×24 grid, DeepGaze IIE) |
| `aesthetics` | 1 score | Aesthetic quality (1–10, LAION model) |
| `yolo` | 85 scores | Object detection counts (80 COCO classes + 5 summary stats) |

Running all models produces ~2,900 feature columns per image/frame.

**EBind** (added 2026-08) is separate from the 11: a 1024-d shared embedding
space spanning vision, text, and audio, so image, caption, word, and movie
features land in one space and can be compared directly. It is extracted
through all three `*2psy` repos.

## Metadata sidecar

Each output CSV has a `.meta.json` sidecar documenting:

- `schema_version` and the extractor name + version
- Per-model `checkpoint` (which weights produced the numbers)
- Input source (paths, frame interval) and output dimensions
- Runtime and device

The `checkpoint` field matters: two runs of the "same model" at different
checkpoints are not comparable, and the sidecar is the only record of which
was used.

## Running extraction

Extraction scripts live in the **mmmdata** repo (`code/mmmdata/scripts/`),
and run in the shared `stimfeat` conda environment
(`/gpfs/projects/hulacon/shared/envs/stimfeat`), which has viz2psy, aud2psy,
word2psy and psytwill installed. GPU required for most models.

```bash
# legacy all-models extraction (writes the stimuli/ layout)
python scripts/run_viz2psy.py images --dry-run
python scripts/run_viz2psy.py movies --frame-interval 1.0
python scripts/run_viz2psy.py images --models resmem emonet aesthetics

# current layout, via the psytwill `features` verb / recipe sbatch
sbatch scripts/stimfeat_ebind.sbatch
```
